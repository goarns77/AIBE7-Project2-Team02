# 마이페이지 교차 도메인 수정 합의 STAR

## Situation | 상황

마이페이지의 구매·판매·채팅 조회를 여러 도메인과 연결하는 과정에서 완료 상태, 활성 거래 판정, Estimate 식별자, 종료 채팅방의 쓰기 정책을 서로 다르게 해석할 가능성이 확인됐다. 활성 거래가 있으면 탈퇴를 차단하는 기본 정책과 결제·정산 흐름은 이미 구현되어 있었으므로, 신규 기능 추가보다 기존 상태를 정확히 연결하고 중복 작업을 피하는 것이 필요했다.

## Task | 과제

진행 거래의 누락과 완료 거래의 과차단을 방지하면서 마이페이지가 원본 도메인의 상태를 임의로 변경하지 않도록 해야 했다. 동시에 현재 구현 범위와 미래 확장 범위를 분리하고, 다른 담당자가 작업 중인 기능을 중복 구현하지 않는 협업 기준을 정해야 했다.

## Action | 행동

현재는 `Payment.COMPLETED`를 거래 완료로 유지하고 준비·배송 등 이행 단계가 추가될 때만 완료 기준을 변경하기로 했다. Proposal·Estimate 상태 전이와 탈퇴 판정 보정은 담당자 작업을 기다린 뒤 회귀 검사하며, Estimate 식별자는 실제 의미가 드러나도록 교정한다. 종료된 채팅방은 읽기 전용으로 유지하고 UI 비활성화뿐 아니라 메시지와 파일 쓰기 요청도 서버에서 차단되는지 확인한다.

## Result | 결과·배움

이미 구현된 정책, 진행 중인 작업, 현재 수정 대상, 미래 기능의 경계가 명확해져 중복 구현과 불필요한 설계 확장을 줄였다. 후속 병합에서는 상태 전이, 탈퇴 판정, 식별자 연결, 종료 채팅방 쓰기 차단만 회귀 검사하면 된다. 다음 프로젝트에서는 완료 기준과 상태 소유권을 먼저 합의하고, UI 제어가 아닌 서버 검증과 통합 테스트로 도메인 간 정책을 고정한다.
